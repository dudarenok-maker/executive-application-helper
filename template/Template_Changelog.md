# Template Package Changelog

This file tracks structural changes to the **template package** — the de-personalised, reusable scaffold in `_Template/` that anyone can use to set up an executive application framework of their own. It is distinct from `Evidence_Bank_Changelog.md` (which tracks the candidate's evidence) and `Project_Instructions_Changelog.md` (which tracks changes to the candidate's live operating instructions).

The maintenance protocol is: whenever a structural change is made to the live framework that would also benefit other users of this package, mirror the change into `_Template/` and append an entry here. Personal content stays in the live files; only structural patterns flow back into the template.

## How to use this log

- One entry per change, in reverse-chronological order (newest first).
- Each entry must capture: date, version transition, files in `_Template/` touched, type of change, rationale, and what a downstream user of the template would notice.
- Group sub-changes under a single date heading when made in one session.
- Do not rewrite history. If an earlier entry is found to be incorrect, add a new entry referring back to it rather than editing the original.

## Change types

- **Major** — new file, new section, new mandatory rule, structural shift in entry format, change to setup flow.
- **Minor** — refinement to placeholder language, additional structural commentary, sharper guidance in skeletons.
- **Editorial** — typo, formatting, deduplication.

## Versioning

The template version **mirrors the candidate's live project-instructions version**: instructions `VX.Y` maps to template `v0.X.Y` (so instructions V5.4 → template **v0.5.4**; a future V6.0 → **v0.6.0**, V6.1 → v0.6.1, and so on). This keeps the published package and the operating instructions legible against each other at a glance. The leading `0.` marks the package as pre-1.0 (still evolving); it rolls to `1.x` only if the framework is ever declared stable for outside users independent of the candidate's own line.

- **The MINOR digit tracks the instructions MAJOR** (V5.x → v0.5.x).
- **The PATCH digit tracks the instructions MINOR** (V5.4 → v0.5.4).
- **A template-only fix** that corresponds to no instructions change takes the next free patch and notes "template-only" in its entry.
- **An instructions-only change** (e.g. housekeeping in the live instructions that does not touch the template skeleton) still advances the template version to keep the mirror in lockstep; its entry notes "mirror-sync — no skeleton content changed."

(Adopted 2026-06-12, retro-applied from v0.5.0 → v0.5.4 to mirror instructions V5.4. Prior history v0.1.0 → v0.4.6 predates the mirror rule and is left as-is.)

## Entry template

```
### YYYY-MM-DD — [short descriptor] — [vX.Y.Z → vX.Y.Z]

- **Type:** Major / Minor / Editorial
- **Files touched:** e.g. `_Template/Project_Instructions.md`; `_Template/Examples_Master.md`
- **Change:** One or two sentences on what changed.
- **Reason:** What in the live framework triggered the update.
- **Downstream impact:** What a user with an existing setup would need to do (or whether nothing is required).
```

### 2026-08-19 — Criteria-response structure, interview research disciplines and panel-room calibration — v0.6.2 → v0.6.5

- **Type:** Major — three new verification checks with their reference specs, and the largest single expansion of the interview-prep template since it was written.
- **Version:** v0.6.2 → **v0.6.5**, mirroring three live instructions passes (V6.3 → V6.4 → V6.5) made the same day. There are no separate v0.6.3 or v0.6.4 template releases; the three passes are mirrored here in one entry because they land as one coherent upgrade for a downstream user.

**What a user of this package gains.**

1. **A criteria response that is scored the way it was built.** `draft-gate` gains **Check 4** (rows 4.1–4.11) and a new `references/criteria-response-structure.md` that is *both* a drafting spec and a gate spec — read before generating the document, verified after. The governing idea is that a Selection Criteria Response is not a document about the candidate; it is a copy of the panel's scoring instrument with the evidence filled in. Every criterion gets its own heading, quoted **verbatim**, grouped under the advertisement's own category headings, in the advertisement's order; one evidence-dense paragraph each, opening with a direct answer and closing on a bridge; compound criteria answered limb by limb; desirables consolidated into one proportionate note; and a clean division of labour with the companion letter, licensed by the letter's single hand-off line. **Blocking rows: 4.2** (criterion inventory complete — a criterion the panel cannot find scores zero, not "partially met"), **4.3** (headings verbatim — a paraphrased heading is functionally a missing criterion), and **4.9** (hard-gate qualification criteria answered head-on — evasion on a stated essential costs more than the gap). A conflict in the old guidance is resolved: a stated page limit now beats the 250–400-word per-criterion default, because eight or nine essentials plus a desirables note will not fit two pages at 250 words apiece. Compress, never pad.
2. **Research a candidate can defend under follow-up.** `prep-gate` gains **Check 5** (rows 5.1–5.9) and `references/research-rules.md`. Sections 3–6 of a prep pack are the only part that asserts things about *other people's companies and other people's careers*, so every claim now carries its epistemic status in words — first-party confirmed, independently corroborated, reasonably corroborated, secondary only, not confirmed, negative finding, inference — with a source-authority ranking and a rule for naming and resolving source conflicts in the document rather than silently picking one. **Blocking rows: 5.4** (every inference labelled and paragraph-isolated — a reformat that strips the `(inference)` label leaves a guess reading as fact), **5.6** (no unsourced claim about a named individual — the failure mode is being corrected by the panellist you were describing), and **5.9** (cross-round information hygiene — intel from one round does not travel into another room).
3. **A pack built for the room it is actually walking into.** `prep-gate` gains **Check 6** (rows 6.1–6.10). The executive summary becomes a **decision instrument** rather than a condensed pack: every named panellist's lens stated, decisions written as directives rather than observations, a core-risks table where every mitigation names the exact section or STAR to deploy, and the time budget stated as arithmetic ("45 minutes, four panellists, 10–13 questions, therefore headline first") rather than as a feeling. Questions and STARs are attributed per panellist — always with the **attribution caveat**, because attribution that reads as prediction makes a candidate *slower* when the wrong person asks. Coaching notes gain four required elements: a **prohibition list** naming what must not be claimed in that answer, delivery discipline, a don't-invent directive **with the substitute sentence supplied** (a prohibition with no substitute leaves the candidate silent; one with a substitute leaves them fluent), and rehearsal priority **ranked across the pack** rather than flagged on every STAR. **Blocking rows: 6.6** (every honest-gap response carries a prohibition list) and **6.9** (cross-artefact consistency).
4. **Cross-artefact consistency as a standing discipline.** New template **§X**: before a prep pack is finalised, reconcile every spoken answer against everything already submitted for that role — cover letter or statement of claims, screening responses in their *final submitted text*, messages to the hiring team, the resume version sent, and every prior-round brief. Same organisation, same figures, same sequence, same admission, same words for the gap. What a written artefact deliberately *withheld* carries forward as a prohibition in the spoken pack. Contradicting your own submitted application in front of a panel that has read it is the one failure no follow-up answer repairs, which is why 6.9 blocks.
5. **A twelve-section prep template.** `Interview_Prep_Template.md` (and its copy in `skills/candidate-voice/references/`) grows from eight sections to twelve: **§R research disciplines**, **§3 company / organisational context**, **§4 operating entities and business units**, **§5 panel and individual research**, **§6 structural-reality analysis** and **§X cross-artefact consistency** join the existing eight, with the research sections placed deliberately **before** the scripts — a pack that writes the scripts first has written them without the research. Also new: a **fourth interview format** (the fit and working-relationship round, which is not a soft behavioural panel and fails characteristically when treated as one), **multi-round progression** conventions (what carries forward unchanged, what is re-cut per round, what must be added every round), round-dependent salary coaching, and depth calibration per listener.
6. **A build directory that stays a build directory.** `Pipeline/` is now **toolchain only** — `build.py`, the design system, the HTML templates, `styles/` and the README, and nothing else. Every work-product source and every built artefact lives in `Submissions/` under a named convention, and builds read from and write back to `Submissions/`. The failure this prevents is a build folder that silently accumulates draft chains and superseded builds until nobody can tell which file was actually sent.

**Skill descriptions re-verified** against the 1,024-character install limit: `draft-gate` 1,016; `prep-gate` 961; `bank-gate` 1,012; `candidate-voice` 917; `coverage-audit` 852.

- **Files touched:** `template/skills/draft-gate/SKILL.md`, `references/checklist.md`, `references/length-bands.md`; `template/skills/prep-gate/SKILL.md`, `references/checklist.md`; `template/skills/candidate-voice/SKILL.md`; `template/Interview_Prep_Template.md`; `template/skills/candidate-voice/references/interview-prep-template.md`; `template/Project_Instructions.md` (current-version line, §5 criteria-structure pointer, §6 file-location convention, §10 prep pointer); `template/Pipeline/README.md`; `template/00_README.md`; `template/Template_Changelog.md` (this entry); `README.md`, `PUBLISHING.md` (version markers, gate descriptions, release procedure). **New:** `template/skills/draft-gate/references/criteria-response-structure.md`, `template/skills/prep-gate/references/research-rules.md`.
- **Reason:** Three live codification passes on the same day, each closing a gap that had existed as practice but never as a written rule. The criteria-structure gap surfaced when a gate that knew the length bands turned out to know nothing about structure. The research and panel-room gaps surfaced from a four-round interview corpus and an executive-panel pack whose richest section was annotated *"added for this session — not part of the standard template"* — which is the clearest possible signal that a template is missing something its users keep having to invent.
- **Downstream impact:** **Additive, not breaking.** A user on v0.6.2 upgrades by (a) copying the two new reference files into `skills/draft-gate/references/` and `skills/prep-gate/references/`, (b) replacing the three changed `SKILL.md` files and the two changed `checklist.md` files, (c) replacing `Interview_Prep_Template.md` and its `candidate-voice` copy — **and then re-reading them**, because the twelve-section structure changes what a prep session should collect before it starts drafting — and (d) re-packaging and re-installing the three gate skills. Existing evidence-bank content, matrix rows and prior prep documents need no migration. One judgement call worth making deliberately: the new blocking rows will stop deliveries that previously went out, which is the intended behaviour, but if a criteria response or prep pack is mid-flight, finish it on the old rules and adopt the new ones from the next role.

Letters follow **two-stage delivery**: an editable review `.docx` first, the final PDF only after the candidate's edits are folded back into the Markdown source.

**Also added:** a mandatory **voice audit** (Mode 4 of `candidate-voice`) that runs before the draft gate and blocks it if skipped, with opener rotation and the em-dash-capped-but-not-zero rule mirrored into `Writing_Voice_and_Style_Guide.md`; the annotation-PDF conventions (page geometry with a wide right margin for margin notes, `\newpage`/Notes blocks, footnote discipline, proportional pipe-table dashes, landscape wrapping, the no-orphaned-page rule) now shipped as `skills/prep-gate/references/annotation-pdf-rules.md`; and a two-phase extension of the setup orchestrator (Phase 4 gates and skills, Phase 5 pipeline), with git initialisation moved to Phase 1 Step 0.

### 2026-05-19 — Duplicate-submission check section added between Mandatory gating step and Lightweight initiation protocol — v0.4.2 → v0.4.3

- **Type:** Minor (additive — new gating-style check inserted between the existing Mandatory gating step and the Lightweight initiation protocol; no change to existing rules; non-breaking for downstream users on v0.4.x).
- **Files touched in `_Template/`:**
  - **`Project_Instructions.md`** — new `## Duplicate-submission check` section inserted between `## Mandatory gating step before drafting` and `## Lightweight initiation protocol`; one-paragraph "Order of operations — strict" preface added to `## Lightweight initiation protocol`; one bullet added at top of `## Pre-drafting assessment` requiring the duplicate-check outcome be recorded.
  - **`Template_Changelog.md`** — this entry; front-matter `last_updated` refreshed to v0.4.3.
- **What a downstream user notices:** Claude (or the equivalent assistant) now runs a three-step duplicate-detection sequence (Glob `Submissions/`; Grep evidence-bank changelog; Grep evidence-bank master file) at the start of every new role kickoff.
